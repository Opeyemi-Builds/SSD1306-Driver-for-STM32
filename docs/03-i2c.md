# 03 - I2C: the bus under the display

Sources: **NXP UM10204** (I2C spec), **RM0390** chapter *I2C interface* (master sequences, CR1/CR2/SR1/SR2/CCR/TRISE), **DS10693** AF table (PB8/PB9 = I2C1 AF4).

## Protocol in 6 lines
- Two wires, SCL (clock) and SDA (data), both **open-drain + pull-up**: devices only pull low.
- START = SDA falls while SCL high. STOP = SDA rises while SCL high.
- Byte = 8 bits MSB first, then the receiver pulls SDA low for **ACK** (high = NACK).
- First byte = 7-bit address + R/W bit. NACK on address = nobody home.
- "Register read" = write the register index, then **repeated START**, then read.
- 100 kHz standard / 400 kHz fast.

## What the STM32F4 hardware wants
Event-driven: set START, wait SB, write address to DR, wait ADDR, clear it by *reading SR1 then SR2*, send bytes when TXE, wait BTF, set STOP. Receiving 1, 2 or 3+ bytes each needs a different ACK/STOP dance (RM0390 diagrams) because the last byte must be NACKed. See `receive_common()`.

## Clock maths (16 MHz APB1)
- CR2.FREQ = 16.
- 100 kHz: CCR = 16 MHz / (2 x 100 kHz) = 80; TRISE = 17.
- 400 kHz: CCR = ceil(16 MHz / (3 x 400 kHz)) = 14 (~380 kHz actual); TRISE = 5.

## Errors handled
NACK (`AF`), arbitration lost (`ARLO`), bus error (`BERR`), per-wait timeout, stuck-busy bus (soft reset). All map to `status_t`.

## Test it
Logic analyzer on PB8/PB9 with an I2C decoder: expect `START, 0x3C W ACK, 0x00 ACK, ...`. Unplug the display: `i2c_probe(0x3C)` must return `STATUS_ERR_NACK` and the NACK shows on the analyzer. Check actual SCL period (~2.6 us at 380 kHz).

Known limits: single master, polling (no interrupts/DMA), no bus-recovery clock pulses, F4 I2C errata not individually handled.
