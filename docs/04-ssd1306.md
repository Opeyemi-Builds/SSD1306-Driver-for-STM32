# 04 - The SSD1306 driver

Source: **SSD1306 datasheet** (Solomon Systech): sections *Command Table*, *GDDRAM*, *I2C-bus interface*. Your module may use a compatible clone (SSD1315/SH1106 differ!), if the picture is shifted 2 px or garbled you probably have an SH1106.

## Layering
```
main.c  ->  ssd1306.c  ->  i2c.c  ->  STM32 I2C1 regs  ->  I2C bus  ->  SSD1306
```
`ssd1306.c` contains zero STM32 register access. It only calls `i2c_mem_write()` and `i2c_probe()`. Port the I2C driver to another MCU and the display driver works unchanged.

## How the chip is talked to
Every I2C write starts with `address+W`, then a **control byte**:
- `0x00` -> following bytes are commands
- `0x40` -> following bytes are pixel data

## Pixel memory (GDDRAM)
128x64 = 8 pages x 128 columns; one byte = 8 vertical pixels, bit 0 on top.
`index = x + (y/8)*128`, `bit = y%8`. The font is stored in the same orientation, so glyph columns copy straight into the buffer.

## Init sequence (datasheet command -> why)
Display off -> clock divide (0xD5) -> multiplex 64 (0xA8) -> offset 0 (0xD3) -> start line (0x40) -> **charge pump on (0x8D,0x14)**, without it the OLED stays dark -> horizontal addressing (0x20,0x00) -> orientation (0xA1, 0xC8) -> COM pin config (0xDA) -> contrast (0x81) -> precharge/VCOMH -> follow RAM (0xA4) -> normal (0xA6) -> display on (0xAF).

## Design decisions
- **Framebuffer in RAM**: drawing costs no bus time; one `flush()` sends 1024 bytes (~25 ms at 400 kHz).
- **Device handle struct** (`ssd1306_t`): address + buffer, so two displays can coexist.
- **Clipping** in all draw calls: out-of-range pixels are ignored, never corrupt memory.
- No ID register on this chip, so `init` uses `i2c_probe()` to detect presence.

## Wiring
VCC->3V3, GND->GND, SCL->PB8 (D15), SDA->PB9 (D14). Address 0x3C (0x3D if the module's address jumper is set).

## Test it
1. Display shows text, counter, and sweeping bar; LED heartbeats.
2. Unplug SDA: LED blinks fast (error path works).
3. Logic analyzer: first transaction is `0x3C W` + `0x00` + the init bytes; flush is `0x3C W`, `0x40`, 1024 data bytes.
4. Change contrast/invert from code and confirm the effect.
5. Try address 0x3D with the display at 0x3C -> `STATUS_ERR_NACK` -> fast blink.
